# สิ่งที่ต่างจากแผนงาน และเหตุผลที่เปลี่ยน
1. เพิ่ม Role ใน ตาราง user เพราะจำเป็นต้องแสดงข้อมูลที่ต่างกันของfrontend
2.  เพิ่มแผนงานสร้างapi สำหรับใส่excal เพื่อแก้ไขข้อมูล เพราะมีการเพิ่มแบบปกติแล้วแต่ยังไม่ได้มีการเพิ่มแบบSKUซ้ำ ไปอัพเดทแค่ข้อมูลด้านใน
3. เพิ่มสมมติฐาน 
    - เพิ่มหน้าสำหรับแก้ไขข้อมูลสินค้าที่ผิดไว้ให้แอดมินแก้ไข
    - ทำfitterกรองสินค้าว่าสินค้าไหน inactive active
 เพราะต้องการให้ระบบสมบูรณ์และใช้งานได้ง่ายขึ้น
4. แก้ฐานข้อมูลuser ไม่เก็บชื่อนามสกุล 
เพราะ แอดมินไม่ได้มีหน้าสมัครสมาชิก

5.  เพิ่มuser_roles ใช้เก็บสิทธิ์ของผู้ใช้
    เพิ่ม user_invitations ใช้เก็บคำเชิญ Admin
    เอาไว้เก็บlog ว่าเชิญไปเมลไหนบ้างและมีrole อะไรบ้าง 

# การใช้ AI: ใช้ทำอะไรบ้าง, ตัวอย่าง prompt อย่างน้อย 3 ตัวอย่าง, AI ผิดพลาดตรงไหนและแก้อย่างไร
1. เขียนโค้ด แก้frontend backend แก้prisma เช็คerror
2. ตัวอย่างprompt
     1. ถ้ามีการใส่ excalตัวใหม่ไปแต่ skuตัวเดิม ให้ไปเอาข้อมูลใหม่ไปอัพเดทลงskuเดิม ถ้าข้อมูลใหม่มีข้อมูลผิดให้ยึดจากข้อมูลเดิมไม่ต้องแก้คอลัมที่ผิด แต่คอลัมอื่นแก้ได้เลย
    2. หน้าแก้ไขเวลาอัพรูปช่วยมีรูปเก่าให้ด้วยไ้มั้ยเพื่อจะลบทิ้ง แล้วก้เอาปุ่มไปไว้ในcontainerเดียวกับ ที่แก้ไขด้วย
    3. if (!sku) errors.push('ไม่มี SKU และไม่พบเลขที่สามารถเติมอัตโนมัติได้');
      else if (!/^LS-\d+$/.test(sku)) errors.push('SKU ต้องขึ้นต้นด้วย LS- และตามด้วยตัวเลข');         ตรวจสอบว่าที่เหลือในแถวนั้นเป้นช่องว่างไหมถ้าใช่ก็ตัดทิ้งไม่ต้องเอาเข้าดาต้าเบส
3. - ตอนแรกที่อัพข้อมูลลงเอไอบันทึกskuแบบไม่แปลงเป็นพิมพ์ใหญ่ มานั่งไล่หาโค้ดแล้วแก้เป็นพิมพ์ใหญ่ก่อนบันทึกลงดาต้าเบส
   - เวลาอัพexcalใหม่เข้าไปในbackend จะเปลี่ยนSKU เพื่อให้ข้อมูลเข้าสู้ระบบได้แต่จริงๆมันคือข้อมูลซ้ำ แก้ด้วยการให้เช็คว่ามีข้อมูลเก่าอยู่แล้วไหมถ้ามีก็ให้แค่อัพเดทไม่ใช่เพิ่มใหม่แล้วเปลี่ยนSKUเอา
